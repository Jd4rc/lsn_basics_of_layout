# lsn_basics_of_layout

Учебный Django-проект: витрина магазина аквариумов, рыбок, растений и сопутствующего
оборудования. Есть вёрстка на шаблонах Django с наследованием от общего макета и
подшаблонами, каталог с постраничным выводом, страницы товаров и категорий, полный
CRUD товаров прямо на сайте (добавление, просмотр, редактирование, удаление), форма
обратной связи, а также регистрация и вход по email с приветственным письмом и профилем
пользователя. Открыты всем только списки товаров и контакты, страницы товара — после входа.
Все вьюхи написаны на классах — generic class-based views Django,
формы — на `ModelForm` с серверной валидацией. Данные — категории, товары, контактная
информация магазина, обращения посетителей и пользователи — хранятся в PostgreSQL, все
модели также доступны в админке.

## Стек

- Python 3.14
- Django 6.1
- Bootstrap 5 (подключён локально из `static/`)
- PostgreSQL (доступ через `psycopg`)
- Pillow — работа с изображениями для `ImageField`
- python-dotenv — переменные окружения из `.env`
- Poetry — управление зависимостями

## Установка

```bash
git clone https://github.com/Jd4rc/lsn_basics_of_layout.git
cd lsn_basics_of_layout
poetry install
```

Создать файл `.env` в корне проекта с настройками подключения к PostgreSQL:

```
SECRET_KEY=django-insecure-...
DEBUG=True
DB_NAME=...
DB_USER=...
DB_PASSWORD=...
DB_HOST=localhost
DB_PORT=5432
```

Для отправки писем (необязательно, см. «Письмо на 100 просмотров») туда же добавляются
`EMAIL_HOST`, `EMAIL_PORT`, `EMAIL_HOST_USER`, `EMAIL_HOST_PASSWORD` и `OWNER_EMAIL` —
образец в `.env.example`.

Применить миграции, загрузить тестовые данные и запустить сервер:

```bash
poetry run python manage.py migrate
poetry run python manage.py load_fixture_catalog
poetry run python manage.py runserver
```

Если виртуальное окружение уже активировано, префикс `poetry run` можно опускать.

Для входа в админку создать суперпользователя — Django спросит email и пароль:

```bash
poetry run python manage.py createsuperuser
```

Загруженные фото товаров лежат в `media/`, а эта папка исключена из репозитория
(`.gitignore`). После свежего клонирования у товаров из фикстуры, для которых указано
фото, картинки не будут найдены — их нужно загрузить заново через админку или форму.
В режиме `DEBUG=True` файлы из `media/` раздаёт сам Django.

| `/users/profile/` | GET, POST | `users:profile` | `UserUpdateView` | `users/user_form.html` | нужен |
| `/<slug>/` | GET | `catalog:category_detail` | `CategoryProductListView` | `catalog/category_detail.html` | — |
| `/admin/` | — | — | — | админка Django | персонал |

Маршруты приложений описаны в `catalog/urls.py` и `users/urls.py` и подключены
в `config/urls.py` через `include()`. Все адреса заканчиваются на `/`. Гостя со страницы,
где нужен вход, перенаправляет на `/users/login/?next=<адрес>`, после входа он
возвращается обратно.

Маршрут категории `/<slug>/` стоит в `catalog/urls.py` последним: он подходит под
любое слово, поэтому все более частные адреса (`contacts/`, `products/...`) должны
проверяться раньше.

### Шаблоны

`templates/base.html` в корне проекта — общий макет: шапка, подвал, подключение
стилей и скриптов. Все страницы наследуются от него через `{% extends 'base.html' %}`
и переопределяют блоки `title` и `content`.

Повторяющиеся куски вынесены в подшаблоны и подключаются через `{% include %}`:

- `templates/includes/nav.html` — навигация: название магазина со ссылкой на главную, пункты
  всех категорий и «Контакты». Гость видит «Войти» и «Регистрация», вошедший — «Добавить
  товар», ссылку на профиль (имя или email) и «Выйти». Подключается в `base.html`, поэтому
  есть на каждой странице.
- `templates/includes/form_fields.html` — поля формы с подписями, подсказками и ошибками,
  включая общие ошибки формы (`non_field_errors`). Ожидает `form`, используется в шаблонах
  `users`.
- `templates/includes/pagination.html` — кнопки «Назад», номера страниц, «Вперёд».
  Ожидает в контексте переменную `page_obj`; если страница всего одна, ничего
  не выводит.
- `catalog/templates/catalog/includes/product_card.html` — карточка товара: фото,
  название со ссылкой на страницу товара, описание, обрезанное до 100 символов
  (`truncatechars:100`), и цена. Ожидает переменную `product`, используется на
  главной и на странице категории.

Список категорий для меню нужен в каждом шаблоне, поэтому его отдаёт контекст-процессор
`catalog.context_processors.menu_categories` (подключён в `TEMPLATES` в
`config/settings.py`) — вьюхам не приходится передавать его самим.

Шаблоны самого приложения лежат в `catalog/templates/catalog/` — вложенная папка
с именем приложения нужна, чтобы имена не конфликтовали с шаблонами других
приложений.

### Вьюхи

Все вьюхи в `catalog/views.py` — классы на основе generic CBV Django. В самих классах
почти только настройки: разбор запроса, формы, 404 и редиректы делает Django.

| Вьюха | Базовый класс | Что делает |
|---|---|---|
| `ProductListView` | `ListView` | главная: товары в продаже, по 6 на странице |
| `CategoryProductListView` | `ListView` | товары категории в продаже, по 6 на странице |
| `ProductDetailView` | `DetailView` | страница товара, считает просмотры, на 100-м шлёт письмо |
| `ProductCreateView` | `CreateView` | добавление товара |
| `ProductUpdateView` | `UpdateView` | редактирование товара |
| `ProductDeleteView` | `DeleteView` | удаление товара с подтверждением |
| `FeedbackCreateView` | `CreateView` + `SuccessMessageMixin` | форма обратной связи, сохраняет обращение |

Страницу товара, добавление, редактирование и удаление закрывает `LoginRequiredMixin`:
он стоит левее базового класса, иначе проверка не сработает. Адрес входа задан
в `LOGIN_URL` в `config/settings.py`. Вьюхи пользователей описаны в разделе «Пользователи».

Шаблоны товара названы по умолчаниям Django (`product_detail.html`, `product_form.html`,
`product_confirm_delete.html`), поэтому `template_name` задан только у главной,
категории и контактов. Оба списка используют собственный миксин `NearestPageMixin`:
при неверном номере страницы он открывает ближайшую, а не отдаёт 404, как `ListView`
по умолчанию.

### Каталог

- **Главная** (`/`) — плитки категорий и блок «Сейчас в наличии»: товары с флагом
  «в продаже», по 6 на странице. Номер страницы передаётся в адресе: `/?page=2`.
  Неверный номер не вызывает ошибку: не число — открывается первая страница,
  слишком большой номер — последняя.
- **Категория** (`/<slug>/`) — описание категории и её товары в продаже, тоже по 6
  на странице с той же пагинацией. Для несуществующей категории — страница 404.
- **Товар** (`/products/<pk>/`) — фото, цена, описание целиком, категория, состояние,
  остаток, флаг «в продаже», даты добавления и обновления, число просмотров, кнопки
  «Редактировать» и «Удалить». Для несуществующего `pk` — страница 404.
  Каждое открытие страницы увеличивает счётчик просмотров на 1; дата «Обновлён»
  от просмотров не меняется. На 100-м просмотре владельцу магазина уходит письмо.

Товары, снятые с продажи, не выводятся в списках, но их страница по прямой ссылке
открывается.

### Добавление и редактирование товара

Страницы `/products/new/` (`ProductCreateView`) и `/products/<pk>/edit/`
(`ProductUpdateView`), форма `catalog.forms.ProductForm` (`ModelForm` на модели
`Product`). Шаблон у обеих один — `product_form.html`: заголовок («Добавить товар» /
«Редактировать товар») и ссылка «Отмена» меняются в зависимости от того, новый
товар в форме или уже сохранённый.

- Поля: категория, название, описание, цена, остаток, состояние, фото, «в продаже».
- При редактировании форма открывается с текущими данными товара; фото можно
  заменить или убрать.
- Проверки на сервере (методы `clean_<поле>` в `ProductForm`):
  - название — не короче 3 символов (пробелы по краям обрезаются);
  - описание — обязательно, не короче 20 символов;
  - в названии и описании нет запрещённых слов: казино, криптовалюта, крипта, биржа,
    дешево, бесплатно, обман, полиция, радар. Список — константа `FORBIDDEN_WORDS`
    в `catalog/forms.py`, регистр не важен, «ё» и «е» не различаются. В ошибке
    перечислены найденные слова;
  - цена — больше нуля. Для отрицательной и для нулевой цены разные сообщения,
    в первом показано введённое значение;
  - фото — необязательно, только JPEG или PNG и не больше 5 МБ. Формат определяется
    по содержимому файла (Pillow), а не по расширению: GIF, переименованный в `.png`,
    не пройдёт. Окно выбора файла сразу показывает только JPEG и PNG (`accept`).
    Если при редактировании новый файл не выбран, старое фото остаётся и повторно
    не проверяется.
- Ошибки выводятся под соответствующими полями, введённые данные при этом
  сохраняются. Исключение — поле «Фото»: браузер не позволяет странице заполнить
  поле выбора файла, поэтому после ошибки файл нужно выбрать заново.
- Форма отправляется с `enctype="multipart/form-data"` — без этого файл не дойдёт
  до сервера. Загруженный файл в форму передаёт сам `CreateView` / `UpdateView`.
- После успешного сохранения — и нового товара, и отредактированного — редирект
  на страницу этого товара (схема Post/Redirect/Get), поэтому обновление страницы
  не отправляет форму повторно. Адрес берётся из `Product.get_absolute_url()`.

### Удаление товара

Страница `/products/<pk>/delete/` (`ProductDeleteView`). GET показывает подтверждение
с данными товара, удаляет товар только POST-запрос по кнопке «Удалить» (с CSRF-токеном),
после чего — редирект на главную. «Отмена» возвращает на страницу товара.

### Письмо на 100 просмотров

Когда товар набирает 100 просмотров, на почту владельца магазина уходит поздравление:
название товара и ссылка на его страницу. Письмо отправляет `catalog/emails.py`,
порог — `VIEWS_MILESTONE` в `catalog/views.py`.

- Почта настроена через `MAILERS` в `config/settings.py` (формат Django 6.1).
  Если в `.env` есть `EMAIL_HOST`, письма уходят по SMTP через SSL (порт 465),
  отправитель — `EMAIL_HOST_USER`. Для Gmail и Яндекса в `EMAIL_HOST_PASSWORD`
  нужен пароль приложения из настроек безопасности аккаунта, обычный пароль не подойдёт.
- Получатель — `OWNER_EMAIL`; если он не задан, письмо уходит на `EMAIL_HOST_USER`,
  то есть самому себе.
- Без `EMAIL_HOST` письма никуда не уходят, а печатаются в консоль `runserver`.
  Тема и текст там закодированы (`=?utf-8?b?...?=` и base64) — так выглядит
  любое письмо с русским текстом, почтовый клиент показывает его нормально.
- Письмо уходит ровно один раз, даже если сотый просмотр пришёлся на несколько
  одновременных открытий. Если почтовый сервер недоступен, страница товара всё равно
  открывается, а ошибка пишется в консоль.

### Пользователи

Вместо стандартного `auth.User` — своя модель `users.User` (`AUTH_USER_MODEL = 'users.User'`),
унаследованная от `AbstractUser`. Поля `username` нет, входят по email
(`USERNAME_FIELD = 'email'`). Дополнительные поля: аватар, номер телефона и страна,
все необязательные. Создаёт пользователей свой `UserManager`, email при входе он сравнивает
без учёта регистра: `Fish@mail.ru` и `fish@mail.ru` — один пользователь.

- **Регистрация** (`/users/register/`) — `UserRegisterForm` на основе `UserCreationForm`:
  email, пароль и повтор пароля. Под полями выводятся ошибки: неверный email, такой
  email уже есть, пароли не совпадают, пароль слишком короткий или простой
  (`AUTH_PASSWORD_VALIDATORS`). После регистрации пользователь сразу входит и попадает
  на главную, а на его email уходит приветственное письмо (`users/emails.py`). Если
  письмо не отправилось, регистрация не ломается, ошибка пишется в лог.
- **Вход** (`/users/login/`) — `UserLoginView` на основе `LoginView` с формой
  `UserLoginForm`: email и пароль. При неверной паре — «Неверный email или пароль.».
  После входа — главная или страница из `?next=`. Вошедшего со страницы входа
  сразу уводит на главную.
- **Выход** — стандартный `LogoutView`, только POST: в меню это кнопка формы
  с CSRF-токеном, а не ссылка. После выхода — главная.
- **Профиль** (`/users/profile/`) — имя, фамилия, телефон, страна и аватар. Телефон можно
  ввести с пробелами, скобками и дефисами, сохраняется он цифрами (`+375291234567`).
  Аватар — JPEG или PNG до 5 МБ, проверка общая с фото товара (`check_image` в
  `catalog/forms.py`). Открыть можно только свой профиль.

### Модели

- **`Category`** — категория товаров (`name`, `description`, `slug`), сортировка
  по названию.
- **`Product`** — товар: `ForeignKey` на `Category` (`on_delete=PROTECT`,
  `related_name='products'`), цена, остаток на складе, состояние (новый, б/у),
  флаг «в продаже» (`is_active`), фото, даты создания и обновления, счётчик
  просмотров (`views_count`, в админке только для чтения). Сортировка — сначала
  новые. `get_absolute_url()` возвращает адрес страницы товара.
- **`ContactInfo`** — контактные данные магазина (телефон, email, адрес, часы
  работы), заполняются через админку и выводятся на странице контактов.
- **`Feedback`** — обращение из формы обратной связи: имя, телефон, email, сообщение
  и дата получения. Сортировка — сначала новые. В админке есть поиск по имени,
  телефону и email.
- **`User`** (приложение `users`) — пользователь: email (уникальный, им входят), пароль,
  имя, фамилия, аватар (`media/users/avatars/`), номер телефона и страна. Подробнее —
  раздел «Пользователи».

У всех моделей есть `__str__` и класс `Meta` с `verbose_name` и `verbose_name_plural`.
Категорию, в которой есть товары, удалить нельзя (`PROTECT`): сначала нужно удалить
товары или перенести их в другую категорию.

### Тестовые данные и management-команды

`catalog_fixture.json` — ассортимент аквариумного магазина: 4 категории
(аквариумы, рыбки, растения, оборудование), 9 товаров и запись с контактами.

- `python manage.py load_fixture_catalog` — загружает фикстуру в базу.
- `python manage.py delete_data_in_db` — удаляет из базы все товары и категории
  (контакты не трогает).

Чтобы пересохранить фикстуру из текущей базы, используйте ключ `-o`:

```bash
poetry run python manage.py dumpdata catalog --indent 2 -o catalog_fixture.json
```

Перенаправление вывода через `>` в PowerShell сохраняет файл не в UTF-8, и русский
текст в фикстуре превращается в нечитаемые символы.

### Форма обратной связи

На странице контактов есть форма с полями «Имя», «Телефон», «Email» и «Сообщение» —
`catalog.forms.FeedbackForm` (`ModelForm` на модели `Feedback`), обрабатывает её
`FeedbackCreateView`.

- Все поля обязательные, имя — до 100 символов, телефон — до 20, email проверяется
  на корректность. Ошибки выводятся по-русски под каждым полем (тексты — в
  `Meta.error_messages`), введённый текст при ошибке не пропадает.
- Отправленное обращение сохраняется в базе, его видно в админке в разделе «Обращения».
- После успешной отправки — редирект обратно на `/contacts/` (Post/Redirect/Get),
  поэтому обновление страницы не отправляет сообщение повторно. Благодарность
  показывается один раз через `django.contrib.messages` (`SuccessMessageMixin`).

Это отдельно от блока контактной информации на той же странице — тот берётся
из модели `ContactInfo` и не связан с отправленной формой.

Форма защищена CSRF-токеном (`{% csrf_token %}` в шаблоне). При отправке запроса
в обход браузера — например, через Postman — нужно сначала выполнить GET, чтобы
получить cookie `csrftoken`, а затем передать её значение в поле
`csrfmiddlewaretoken` или в заголовке `X-CSRFToken`. Иначе Django вернёт
403 с текстом «CSRF verification failed».

### Оформление

Собственные стили — в `static/css/style.css`. Визуальная идея взята с киноафиши:
пыльно-розовый фон, крупные серифные заголовки, подписи узким гротеском в верхнем
регистре, чёрные рамки без скруглений и SVG-зерно поверх страницы. Фото в карточках
обрезаются до одинаковой высоты (`object-fit: cover`), длинные слова без пробелов
переносятся, а не вылезают за блок.

Поля форм оформляет `StyleFormMixin` из `catalog/forms.py`: в `__init__` он проходит
по полям и по типу виджета добавляет классы — `form-control input-ink` для текстовых
полей и загрузки файла, `form-select input-ink` для списков, `form-check-input check-ink`
для чекбокса. Миксин ставится левее `ModelForm` (`class ProductForm(StyleFormMixin,
forms.ModelForm)`), его используют обе формы проекта. Чекбокс «В продаже» выводится
в блоке `form-check`: квадрат с чёрной рамкой, подпись справа.

### Известные ограничения

- У товара нет владельца: любой вошедший пользователь может редактировать и удалять
  любой товар.
- Восстановления пароля нет: забытый пароль меняется только через админку.
- Приветственное письмо уходит внутри запроса регистрации: при медленном SMTP
  страница ждёт до 10 секунд (`timeout` в `MAILERS`).
- Запрещённые слова ищутся как подстрока: «обмана» будет найдено, а другие формы
  слова — например, «полиции» — нет.
- При удалении товара файл фото остаётся в `media/products/`, при замене аватара старый
  файл остаётся в `media/users/avatars/`.
- Категория со слагом `contacts` или `admin` будет недоступна: эти адреса раньше
  перехватят страница контактов и админка.
