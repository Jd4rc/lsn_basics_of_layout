# lsn_basics_of_layout

Учебный Django-проект: витрина магазина аквариумов, рыбок, растений и сопутствующего
оборудования. Есть вёрстка на шаблонах Django с наследованием от общего макета и
подшаблонами, каталог с постраничным выводом, страницы товаров и категорий, форма
добавления товара с валидацией и форма обратной связи. Данные — категории, товары и
контактная информация магазина — хранятся в PostgreSQL и редактируются через админку.

## Стек

- Python 3.14
- Django 6.1
- Bootstrap 5 (подключён локально из `static/`)
- PostgreSQL (доступ через `psycopg`)
- Pillow — работа с изображениями для `ImageField`
- load-dotenv / python-dotenv — переменные окружения из `.env`
- Poetry — управление зависимостями

## Установка

```bash
git clone https://github.com/Jd4rc/lsn_basics_of_layout.git
cd lsn_basics_of_layout
poetry install
```

Создать файл `.env` в корне проекта с настройками подключения к PostgreSQL:

```
SECRET_KEY=django-insecure-...
DEBUG=True
DB_NAME=...
DB_USER=...
DB_PASSWORD=...
DB_HOST=localhost
DB_PORT=5432
```

Применить миграции, загрузить тестовые данные и запустить сервер:

```bash
poetry run python manage.py migrate
poetry run python manage.py load_fixture_catalog
poetry run python manage.py runserver
```

Если виртуальное окружение уже активировано, префикс `poetry run` можно опускать.

Загруженные фото товаров лежат в `media/`, а эта папка исключена из репозитория
(`.gitignore`). После свежего клонирования у товаров из фикстуры, для которых указано
фото, картинки не будут найдены — их нужно загрузить заново через админку или форму.
В режиме `DEBUG=True` файлы из `media/` раздаёт сам Django.

## Страницы

| URL | Метод | Имя маршрута | Шаблон |
|---|---|---|---|
| `/` | GET | `catalog:home` | `catalog/home.html` |
| `/contacts/` | GET, POST | `catalog:contacts` | `catalog/contacts.html` |
| `/products/new/` | GET, POST | `catalog:product_create` | `catalog/product_form.html` |
| `/products/<int:pk>/` | GET | `catalog:product_detail` | `catalog/product_detail.html` |
| `/<slug>/` | GET | `catalog:category_detail` | `catalog/category_detail.html` |
| `/admin/` | — | — | админка Django |

Маршрут категории `/<slug>/` стоит в `catalog/urls.py` последним: он подходит под
любое слово, поэтому все более частные адреса (`contacts/`, `products/...`) должны
проверяться раньше.

### Шаблоны

`templates/base.html` в корне проекта — общий макет: шапка, подвал, подключение
стилей и скриптов. Все страницы наследуются от него через `{% extends 'base.html' %}`
и переопределяют блоки `title` и `content`.

Повторяющиеся куски вынесены в подшаблоны и подключаются через `{% include %}`:

- `templates/includes/nav.html` — навигация: название магазина со ссылкой на главную, пункты
  всех категорий, «Добавить товар» и «Контакты». Подключается в `base.html`, поэтому
  есть на каждой странице.
- `templates/includes/pagination.html` — кнопки «Назад», номера страниц, «Вперёд».
  Ожидает в контексте переменную `page_obj`; если страница всего одна, ничего
  не выводит.
- `catalog/templates/catalog/includes/product_card.html` — карточка товара: фото,
  название со ссылкой на страницу товара, описание, обрезанное до 100 символов
  (`truncatechars:100`), и цена. Ожидает переменную `product`, используется на
  главной и на странице категории.

Список категорий для меню нужен в каждом шаблоне, поэтому его отдаёт контекст-процессор
`catalog.context_processors.menu_categories` (подключён в `TEMPLATES` в
`config/settings.py`) — вьюхам не приходится передавать его самим.

Шаблоны самого приложения лежат в `catalog/templates/catalog/` — вложенная папка
с именем приложения нужна, чтобы имена не конфликтовали с шаблонами других
приложений.

### Каталог

- **Главная** (`/`) — плитки категорий и блок «Сейчас в наличии»: товары с флагом
  «в продаже», по 6 на странице. Номер страницы передаётся в адресе: `/?page=2`.
  Используется `Paginator.get_page`, поэтому неверный номер не вызывает ошибку:
  не число — открывается первая страница, слишком большой номер — последняя.
- **Категория** (`/<slug>/`) — описание категории и её товары в продаже.
- **Товар** (`/products/<pk>/`) — фото, цена, описание целиком, категория, состояние,
  остаток, флаг «в продаже», даты добавления и обновления. Для несуществующего
  `pk` — страница 404 (`get_object_or_404`).

Товары, снятые с продажи, не выводятся в списках, но их страница по прямой ссылке
открывается.

### Форма добавления товара

Страница `/products/new/`, вьюха `catalog.views.product_create`, форма
`catalog.forms.ProductForm` (`ModelForm` на модели `Product`).

- Поля: категория, название, описание, цена, остаток, состояние, фото, «в продаже».
- Проверки на сервере:
  - название — не короче 3 символов (пробелы по краям обрезаются);
  - описание — обязательно, не короче 20 символов;
  - цена — больше нуля.
- Ошибки выводятся под соответствующими полями, введённые данные при этом
  сохраняются. Исключение — поле «Фото»: браузер не позволяет странице заполнить
  поле выбора файла, поэтому после ошибки файл нужно выбрать заново.
- Форма отправляется с `enctype="multipart/form-data"`, а во вьюхе передаётся
  `request.FILES` — без этого файл не дойдёт до сервера.
- После успешного сохранения — редирект на страницу нового товара (схема
  Post/Redirect/Get), поэтому обновление страницы не создаёт дубль.

### Модели

- **`Category`** — категория товаров (`name`, `description`, `slug`).
- **`Product`** — товар: `ForeignKey` на `Category` (`on_delete=PROTECT`,
  `related_name='products'`), цена, остаток на складе, состояние (новый, б/у),
  флаг «в продаже», фото, даты создания и обновления.
- **`ContactInfo`** — контактные данные магазина (телефон, email, адрес, часы
  работы), заполняются через админку и выводятся на странице контактов.

### Тестовые данные и management-команды

`catalog_fixture.json` — ассортимент аквариумного магазина: 4 категории
(аквариумы, рыбки, растения, оборудование), 9 товаров и запись с контактами.

- `python manage.py load_fixture_catalog` — загружает фикстуру в базу.
- `python manage.py delete_data_in_db` — удаляет из базы все товары и категории
  (контакты не трогает).

Чтобы пересохранить фикстуру из текущей базы, используйте ключ `-o`:

```bash
poetry run python manage.py dumpdata catalog --indent 2 -o catalog_fixture.json
```

Перенаправление вывода через `>` в PowerShell сохраняет файл не в UTF-8, и русский
текст в фикстуре превращается в нечитаемые символы.

### Форма обратной связи

На странице контактов есть форма с полями «имя», «телефон» и «сообщение».
POST-запрос обрабатывается во вьюхе `catalog.views.contacts`: данные читаются
из `request.POST`, выводятся в консоль сервера, после чего страница
перерисовывается с сообщением об успешной отправке. Это отдельно от блока
контактной информации на той же странице — тот берётся из модели `ContactInfo`
и не связан с отправленной формой.

Форма защищена CSRF-токеном (`{% csrf_token %}` в шаблоне). При отправке запроса
в обход браузера — например, через Postman — нужно сначала выполнить GET, чтобы
получить cookie `csrftoken`, а затем передать её значение в поле
`csrfmiddlewaretoken` или в заголовке `X-CSRFToken`. Иначе Django вернёт
403 с текстом «CSRF verification failed».

Хранение отправленных сообщений в базе, валидация через `forms.Form` и редирект
после отправки пока не реализованы.

### Оформление

Собственные стили — в `static/css/style.css`. Визуальная идея взята с киноафиши:
пыльно-розовый фон, крупные серифные заголовки, подписи узким гротеском в верхнем
регистре, чёрные рамки без скруглений и SVG-зерно поверх страницы. Фото в карточках
обрезаются до одинаковой высоты (`object-fit: cover`), длинные слова без пробелов
переносятся, а не вылезают за блок.
